Reworked the automated release workflows. The `mathieudutour/github-tag-action` dependency was replaced with plain git commands, which also tag the actual merge commit instead of the ephemeral PR merge ref now. The GitHub App for release automation (`AUTORELEASE_CLID`/`AUTORELEASE_PRIV` secrets) is now additionally used to push the release tag when the autorelease PR is merged, meaning all releases are handled by the regular tag push workflow (`tag.yml`) instead of a separate entry point. A new question `require_autorelease_app` (defaults to true for repositories inside the `salt-extensions` organization) renders significantly simpler release workflows that require the app, otherwise they still support falling back to the default GitHub token. Following PyPI's recommendation of minimal Trusted Publisher workflows, `deploy-package-action.yml` was reduced to artifact verification and publishing only - its publish jobs now republish the exact verified bytes and dropped unnecessary permissions, while the GitHub release and docs deployment moved to a new `finalize-release-action.yml` workflow outside the publishing trust boundary.
